## 1. 백엔드

### 1-1. 공통 3가지 확인

| 항목      | 초안 내용                                                                           |
| --------- | ----------------------------------------------------------------------------------- |
| 기본 주소 | `/api`                                                                              |
| 응답 틀   | 성공 `{ success: true, data }`, 실패 `{ success: false, error: { code, message } }` |
| 익명 ID   | `POST /api/session` → `anonymousId`. 이후 요청마다 `X-Anonymous-Id` 헤더            |

### 1-2. 꼭 필요한 것

1. **배포 주소(HTTPS)** — 프론트가 `/api` 요청을 이 주소로 넘겨요
2. **데모 4개** — `GET /api/demo/state`(today) · `POST /api/demo/next-day`(judgment: carry · replan · none) · `/reset` · `/seed`
3. **시드** — 이름은 `empty` · `day9` · `overdue`, 값은 데모 패키지 3과목(인공지능 · 데이터베이스 · 운영체제) 기준
4. **시드 값표 공유** — 프론트 목업과 시연 대본을 이 값에 맞춰요
   - 과목 · 시험일 · 목표
   - 단원(페이지)
   - 오늘 할 일 · 진행률 · 준비도 · 밀린 페이지
5. **데모 과목 ID** — 초안 예시는 `ds` · `t1`이에요. 실제 ID를 알려 주세요
6. **시드에서 시연 장면이 나오는지 확인**

| 장면        | 시드      | 필요한 상태                                                                                       |
| ----------- | --------- | ------------------------------------------------------------------------------------------------- |
| 계획 만들기 | `empty`   | S1~S5. 스캔본은 글자 인식(OCR)으로 분석 → '퀴즈 없음', 분석이 안 되는 파일은 목차 직접 입력(S3-2) |
| 시연일 홈   | `day9`    | 오늘 할 일 여러 개, 진행률 70% 미만                                                               |
| 공부 기록   | `day9`    | 부분 완료로 70%를 넘기면 하루 마무리 박스(P1)                                                     |
| 퀴즈        | `day9`    | 서술형 포함 → 채점 피드백 → 책 쌓기 변화(P3, `bookChanges`)                                       |
| 책 쌓기     | `day9`    | 위험(빨강) 단원 1개 이상                                                                          |
| 밀림 · 회복 | `overdue` | '다음 날로' → judgment `replan` → 분배안 3개(P2) → 하나 고르면 회복 박스                          |

### 1-3. AI 응답 시간 (30초)

- 초안은 AI 응답을 **최대 30초** 기다리는 방식이에요. 30초가 지나면 프론트는 실패로 보고 다시 시도를 보여줘요
- S3 PDF 분석만 `GET /api/materials/jobs/:jobId`로 단계를 확인해요
- 30초를 넘길 수 있는 곳이 있으면 알려 주세요: 계획 생성(S5) · 다시 나누기(S5-1) · 퀴즈 준비(S8) · 채점(S8-3) · 튜터(S6-3) · 분배안(P2)

### 1-4. 같이 정할 것 (초안의 빈칸)

1. **진행 단계** — AI 대기 화면의 진행 단계를 서버가 알려 줄지. 지금은 프론트가 1.2초마다 넘겨요
2. **저장된 결과** — AI가 실패했을 때 보여줄 저장된 결과(`saved`)의 규칙 (초안 '공통 · AI 상태' 표)

### 1-5. 확인만 부탁하는 것

1. 필드를 바꾸거나 못 주는 게 있으면 구현 전에 알려 주세요. 프론트는 adapters 한 곳에서 맞춰요
2. S1 일정 대화가 시연 문장으로 동작하는지. AI 명세의 9개 엔드포인트에는 일정 해석이 없어요
3. 사용자가 올린 PDF가 AI 서버에 어떻게 가는지. AI의 `/ai/quiz/generate`는 AI 서버 폴더 경로(`pdf_path`)를 받아요. S3 업로드 시연이 여기에 걸려 있어요
4. 진행률 · 숙달도 · 준비도를 백엔드와 AI 중 어디서 계산할지. AI의 `/ai/learning/metrics`도 비슷한 값을 계산해요

### 1-6. 있으면 좋은 것

- `/api/demo/ai` (AI 느림 · 실패 재현). 초안에 있지만, 없으면 목업 모드에서만 보여줘요
- API 응답에 `Cache-Control: no-store` (Vercel 중계가 응답을 저장하지 않게. 프론트도 vercel.json에서 막아요)

### 1-7. 프론트가 먼저 정한 것 (알림)

- 서버 연결은 프론트 주소에서 `/api` 중계 (백엔드 CORS 설정 불필요)
- AI 응답은 30초까지 기다리고, 지나면 실패로 보고 다시 시도 (초안 규칙)
- `/dev` AI 느림 · 실패 재현은 서버에 없으면 목업 모드에서만
- AI 회고 화면은 넣지 않아요

### 1-8. 오후 요청 중 취소

- 쿠키 Domain, Job(202) · 멱등 키
- 오류 코드 전체 목록 (초안의 `error.code` 사용)
- S6-2 이월 값 · S9 단원 메모 (초안 · 목업 응답 기준으로 구현)
- AI 회고, 새 세션에서 데모 시드가 되는지

## 2. AI (현민님)

카톡 전달 내용 기준이고, 22시에 백엔드가 프론트 API 초안에 맞추기로 해서 고쳤어요. 프론트는 AI를 직접 부르지 않고 백엔드를 거쳐 받아요.

### 2-1. 시연 확인 (이미 있으면 필드 이름만)

- 서술형 점수 · 맞힌 요소 · 빠진 요소
- 문제별 근거 문장(quote). 프론트가 원본 PDF에서 이 문장을 찾아 하이라이트해요
- 유형 · 난이도 · 보기 ID
- 단원마다 '하' 문제 5개 이상 (1회독 퀴즈는 '하' 난이도로 단원당 5문제)

### 2-2. 스캔본 분석 결과

- OCR 성공인지, 422 실패인지
- 시연은 OCR로 분석 → '퀴즈 없음'이고, 분석 자체가 실패할 때만 목차 직접 입력이에요 (정의서 v2 PDF-01 · PDF-07)

### 2-3. 단원 수 · 소요 시간

- 단원 수: 문제은행 테스트는 AI1~AI4(4개), 데모 JSON의 인공지능 PDF는 대단원 3개
- 소요 시간: 실시간 분석(8p) · 문제 생성 · 서술형 채점 · 튜터가 30초 안에 끝나는지

### 2-4. 백엔드와 맞출 것

- 올린 PDF 전달 (`pdf_path`)
- 대화형 목표 설정 · 일정 대화 엔드포인트 (충족 표에는 있는데 9개 목록에 없음)
- 학습 지표 계산 담당 (백엔드도 단원 점수 · 등급 · 준비도를 계산할 수 있음)

### 2-5. 여유 있을 때

- 실제 응답 전체 필드 예시
- 단원 필드 이름 통일 (분석은 `id · name · page_start`, 문제은행은 `unit_id`, 데모 JSON은 `section_title · start_page`)
- 오류 `{ code, message }`
- `done_pages` 예시를 데모 과목으로 (지금은 DS · OS · NW)
- JSON 예시는 4장

### 2-6. 프론트가 먼저 정한 것

- 필드 이름 · 확신도(확실 · 애매) 변환은 백엔드에서
- 튜터는 프론트 초안(`{ question, history }` → `{ answer, pages }`)이 지금 구조와 같아서 그대로. 근거는 `pages`로 충분 (과목당 PDF 1개)
- 처리 시간 안내는 8초 · 30초 규칙 (30초가 지나면 실패로 보고 다시 시도)
- AI 회고는 준비하지 않아도 돼요

## 3. 기획

1. **데모 패키지 기준으로 데이터 세트 · 시연 대본 다시 정리** (백엔드 시드 값에 맞춰)
   - S1 입력 문장
   - 과목별 시험일 · 목표
   - 튜터 질문 (지금은 AVL 회전)
   - 서술형 · 오답 장면 페이지
2. **스캔본 장면**
   - 데이터 세트: '분석 실패 → 목차 직접 입력'
   - 정의서 v2(PDF-01 · 07)와 프론트 초안: 'OCR 분석 → 퀴즈 없음'
   - 시연 대본을 어느 쪽으로 할지 정해 주세요. 목업은 둘 다 돼요 (파일 이름에 '스캔'이 있으면 OCR · 퀴즈 없음, '실패'가 있으면 분석 실패)
3. **P4 속도 보정과 P2 분배안이 같은 날 겹칠 때 순서**

## 4. JSON 예시 (AI ↔ 백엔드 참고 제안)

백엔드와 AI가 정할 내용이에요. 이름은 AI 쪽 규칙(snake_case)대로 두고, 백엔드가 바꿔요. `//` 주석은 설명용이에요.

### 4-1. PDF 분석 응답 (`/ai/analyze`)

```jsonc
{
  "extraction_method": "text", // text | ocr
  "ocr_confidence": null, // ocr일 때 0~1
  "units": [
    {
      "unit_id": "AI1",
      "title": "머신러닝 기초",
      "order": 1,
      "start_page": 3,
      "end_page": 11,
      "difficulty": "low",
      "concepts": [
        { "concept_id": "AI1-2", "title": "특성과 레이블", "start_page": 4, "end_page": 4 },
      ],
    },
  ],
}
```

### 4-2. 문제 객체 (`/ai/quiz/generate`, 채점용)

```jsonc
{
  "question_id": "AI1-Q03",
  "unit_id": "AI1",
  "concept_id": "AI1-3",
  "type": "choice", // choice | short | essay
  "difficulty": "low", // low | mid | high
  "prompt": "문제 본문",
  "choices": [
    { "id": "A", "text": "보기 1" },
    { "id": "B", "text": "보기 2" },
  ],
  "answer": "B",
  "explanation": "해설",
  "sources": [{ "start_page": 5, "end_page": 5, "quote": "근거 문장" }],
}
```

### 4-3. 채점 응답 (`/ai/quiz/grade`)

```jsonc
{
  "total_questions": 5,
  "results": [
    {
      "question_id": "AI1-Q03",
      "is_correct": false,
      "essay_score": 70, // essay만
      "feedback": "피드백", // essay만
      "got_points": ["맞힌 요소"],
      "missing_points": ["빠진 요소"],
      "correct_answer": "정답",
      "explanation": "해설",
    },
  ],
}
```
