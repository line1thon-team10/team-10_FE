## 2. 작업 방식 (사용자 지침 — 꼭 지켜요)

속도보다 "다시 고치지 않아도 되는 코드"가 우선이에요.

### 2-1. 확정의 기준

확정인 것

- 사용자가 대화에서 명시적으로 결정·승인한 내용
- 프로젝트 파일(`docs/`, `GATES.md`)이나 기존 코드에 이미 정해진 내용
- 팀 규칙 (Git 규칙 등)

확정이 아닌 것

- "보통 이렇게 한다"는 Claude의 판단
- Claude가 제안만 하고 사용자가 고르지 않은 것
- Figma 시안 (사용자가 "시안대로 만들어줘"라고 할 때만 확정)
- 백엔드·AI·기획 담당 영역의 API 경로, 요청/응답 필드명, 데이터 구조 (실제 명세를 받을 때만 확정)

예외: 한 파일에 모이는 값(API 경로·필드, AI 응답 형식, 상태 색, 문구)은 임시값으로 진행하고 `TODO(확인필요)`를 달아요 (CLAUDE.md 표시 주석).

### 2-2. 멈추고 물어야 할 때

- 요구사항이 두 가지 이상으로 해석될 때
- 필요한 정보가 없을 때 (API 명세, 데이터 구조, 화면 흐름, 환경변수, 디자인 값)
- 팀원 담당 영역과 맞물릴 때 (예: AI 분석 결과 JSON 형식)
- 새 라이브러리 추가·버전 변경, 폴더 구조·라우팅·상태관리 방식 변경
- 기존에 동작하던 코드의 삭제·대규모 수정
- 되돌리기 어려운 작업: force push, reset --hard, 브랜치·데이터 삭제, 배포 설정·환경변수 변경
- 요청이 기존 코드, 확정 사항, 활성 게이트와 충돌할 때
- 같은 오류를 2번 고쳐도 남을 때

질문은 한 번에 모아서 이 형식으로 해요. 열린 질문만 던지지 말고 선택지와 추천을 붙여요.

```
[확인 필요 — 작업 중지]
지금까지 확정된 것: …
모르는 것 / 헷갈리는 것:
Q1. (질문)
  - A안: … (장단점)
  - B안: … (장단점)
  - 추천: A안 — 이유
→ 답변을 받으면 확정 요약 후 진행합니다.
```

- "일단 이렇게 가정하고 진행"하지 않아요. 사용자가 "가정하고 진행해"라고 했을 때만 가정을 표시하고 진행해요.
- 사용자가 "확정된 것부터 진행"이라고 하면 확정 부분만 먼저 만들고, 미확정 부분은 `// TODO(확인필요): 내용`으로 남겨요.
- 가짜 데이터는 코드 주석과 화면 MOCK 배지로 mock이라고 표시해요.

### 2-3. 착수 점검 (코드를 쓰거나 고치기 전에 매번)

```
[착수 점검]
- 작업 범위: 이번에 만들거나 고칠 것
- 확정 사항: 근거(사용자 결정 / 기존 코드 / 프로젝트 파일)와 함께
- 미확정 사항: 없음  ← 하나라도 있으면 2-2 형식으로 멈춤
- 적용 게이트: G-00X(제목) … / 해당 없음
```

오타·문구 수정 같은 아주 작은 작업은 "적용 게이트: 해당 없음" 한 줄로 줄여도 돼요.

### 2-4. 오류가 났을 때

- 땜질 수정을 반복하지 않아요. 같은 오류에 수정 2회 실패하면 멈추고 보고해요.
  - 지금까지 시도한 것과 결과
  - 원인 가설 (가능성 높은 순)
  - 확인에 필요한 정보 (콘솔 로그, Network 탭, 환경변수, 실행 명령)
- 원인을 확인하기 전에는 "해결됐다"고 말하지 않아요. 고친 뒤에는 확인 방법을 같이 알려 줘요.
- 해결되면 `docs/GATES.md` 형식으로 게이트 초안을 제안해요. **사용자가 승인한 것만** 등록해요.
- 활성 게이트의 '금지 경로'는 다시 쓰지 않아요. 요청이 게이트에 걸리면 번호와 이유를 알리고 '대신 할 것'을 제안해요.

### 2-5. 답변 마무리 (개발 작업 끝에 짧게)

- 이번에 반영한 확정 사항
- 남아 있는 미확정 사항 (없으면 생략)
- 새로 제안하는 게이트 (있을 때만)

## 7. 코드 구조 요약

자세한 폴더 설명은 `docs/structure.md`예요.

- 데이터 흐름: 화면 → `hooks/` → `api/*.js` → `api/adapters/` → (실제 서버 | MSW 목업)
- 서버 응답 모양은 `api/adapters/`에서만 다뤄요. API 경로는 `api/endpoints.js`에서만 정해요
- 목업 서버 (`src/mocks/`)
  - `data/seed.js`: 데이터 세트 값. 데이터 세트에 없는 값은 주석으로 mock 표시
  - `db.js`: 메모리 가짜 DB. 시드 3개(`empty`, `day9`, `overdue`), `seed()`, `reset()`
  - `logic.js`: 서버 계산 흉내 — 오늘 화면, 다음 날로 판정(이월/분배안), 분배안 적용, 퀴즈 채점, 책 쌓기
  - `handlers/*.js`: 주소별 응답. `respond.run()`이 `MockError`를 실패 응답으로 바꿔요
- 새 API를 붙이는 순서: `endpoints.js` → `mocks/handlers` (+`logic.js`) → `api/adapters` → `api/*.js` → `hooks` (+`queryKeys.js`) → 화면

실제 서버로 바꿀 때 (11/13 · 11/14 기준)

1. 받은 명세와 지금 형식(`adapters`, `endpoints.js`, `seed.js`)을 비교한 표를 먼저 만들어 사용자에게 보여줘요 (G-2: 기준 확인 → `docs/policy-and-backend.md`에 결정 기록 → 보관 브랜치 → 코드)
2. `endpoints.js`, `api/adapters/`, `mocks/`만 고쳐요. 화면 코드는 고치지 않는 게 목표예요
3. `.env`에 `API_PROXY_TARGET=서버 주소` [임시]와 `VITE_USE_MOCK=hybrid`(서버에 있는 경로만 서버) 또는 `false`(전부 서버). `VITE_API_BASE_URL`은 비워 둬요 — 개발 서버(`npm run dev`)가 `/api`를 프록시해요. 환경변수 변경은 사용자 확인 후, Vercel 설정은 건드리지 않아요
4. 시연 순서를 처음부터 끝까지 두 모드(`true` · `hybrid`)로 확인해요. 제출 · 영상은 `true`(목업)예요

혼합 모드 규칙 (`VITE_USE_MOCK=hybrid`)

- 서버로 보내는 경로 22개는 `src/mocks/hybrid.js`의 `SERVER_ROUTES` 한 곳에만 있어요. 서버에 경로가 생기면 여기에 한 줄 추가해요
- 경로나 본문의 ID(`taskId` · `:key` · `:subjectId` · `:id`)가 UUID가 아니면 목업이 처리해요 (목업 ID로 서버를 부르지 않게)
- demo seed · reset · next-day는 서버로 보내고, 성공하면 목업도 같은 시드 · 같은 날로 맞춰요. S5 승인(목업)은 서버에도 `demo/seed day9`를 먼저 보내요
- 401 `NO_SESSION` · `UNKNOWN_SESSION`이면 익명 ID를 새로 받아 1번만 다시 보내요. 목업 때 저장된 `mock-…` ID는 서버에 보내지 않고 지워요

## 10. 지난 작업에서 겪은 것 (게이트 아님, 참고)

- 컴포넌트 파일(`.jsx`)에서는 컴포넌트만 export해요. 공용 함수는 `src/lib/`로 (react-refresh 린트, 화면 갱신 오류)
- 렌더 중에 `Date.now()`, `URL.createObjectURL()` 같은 부수효과를 쓰지 않아요 → `useEffect`·`useMemo`·이벤트에서 (React 19 린트)
- '오늘'은 서버 데모 날짜예요. `dayjs()`로 현재 시각을 쓰지 않고 `config/date.js` 함수와 서버 `today`를 써요
- 분석 중인 자료는 목록을 1초마다 다시 불러와야 상태가 바뀌어요 (`useMaterials`)
- `public/mockServiceWorker.js`는 MSW가 만든 파일이에요. 지우거나 고치지 않아요
- 자동 브라우저 테스트(Playwright)를 쓸 때: 흔들리는 책은 계속 움직여서 클릭에 `{ force: true }`가 필요하고, 한글 경로 파일 업로드는 0개로 들어가서 `{ name, mimeType, buffer }`로 넣어야 해요. Playwright는 저장소 의존성에 없어요 (추가하려면 먼저 물어요)
